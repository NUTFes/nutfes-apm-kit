# 横断レビュー観点（全PR共通）

技術スタックを問わず、すべてのPRで確認する項目。

## セキュリティ

- [ ] 秘密情報（APIキー・トークン・パスワード）がハードコードされていないか
- [ ] ユーザー入力のバリデーション・サニタイズが行われているか
- [ ] 認可チェック（他人のリソースにアクセスできてしまわないか）が抜けていないか

## パフォーマンス

- [ ] ループ内でのDB呼び出しなど、N+1を誘発する実装になっていないか
- [ ] 不要な全件取得・ページネーション漏れがないか

## エラーハンドリング

- [ ] 例外やエラーレスポンスが握りつぶされていないか
- [ ] 障害調査に必要なコンテキスト（リクエストID等）がログに残るか

## テスト

- [ ] 変更した挙動に対応するテストが追加・更新されているか
- [ ] 空配列・null・境界値などのエッジケースがカバーされているか

## 可読性・保守性

- [ ] 命名が処理内容を正確に表しているか
- [ ] 同じロジックの重複がないか
- [ ] 変更の意図がコミットメッセージ・PR説明から読み取れるか
