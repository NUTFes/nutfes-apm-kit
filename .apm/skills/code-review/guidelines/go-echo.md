# Go (Echo) レビュー観点

> このファイルはテンプレートです。認証ミドルウェアの設計方針、論理削除のルールなど、
> 実際のプロジェクトの既存の設計判断に合わせて追記してください。

## ハンドラ設計

- [ ] エラーが握りつぶされず `echo.HTTPError` として適切なステータスで返っているか
- [ ] 認証・認可ミドルウェアの適用漏れがないか
- [ ] リクエストのバリデーションがハンドラ内に散らばっていないか

## データ設計

- [ ] 論理削除（soft delete）対象のテーブルであれば、削除フラグを考慮したクエリになっているか
- [ ] 外部通知（Slack Webhook・メール送信等）が失敗した場合のリトライ・エラーハンドリングがあるか

## 並行処理・堅牢性

- [ ] goroutine内のエラーが握りつぶされていないか（panic時のrecoverも含む）
- [ ] `context` 経由のタイムアウト・キャンセルが下位の呼び出しまで伝播しているか

## 設定・シークレット

- [ ] 環境変数・設定値のデフォルトが本番環境で安全な値になっているか
